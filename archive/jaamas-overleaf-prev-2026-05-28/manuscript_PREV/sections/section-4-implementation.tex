\subsection{Backend implementation}\label{sec:4-backend}

\leadpara{Gateway and route map.}
The HTTP entry point is \texttt{backend/gateway/app.py}: a FastAPI application (\texttt{build\_gateway}) wired to a \texttt{SystemContainer} from \texttt{bootstrap.py}.
Routers mount at the application root (no global \texttt{/api} prefix):
\texttt{/auth} (\texttt{auth/routes.py}),
\texttt{/agents} (\texttt{gateway/routes/agents.py}),
\texttt{/candidates} (\texttt{gateway/routes/candidates.py}),
\texttt{/jobs} (\texttt{gateway/routes/employers.py}),
\texttt{/match/*} and legacy aliases (\texttt{gateway/routes/matching.py}),
\texttt{/similar} (\texttt{gateway/routes/similar.py}),
\texttt{/feedback} (\texttt{gateway/routes/feedback.py}),
\texttt{/system} (\texttt{gateway/routes/system.py}),
\texttt{/real-jobs} (\texttt{gateway/routes/real\_jobs.py}).
Middleware: \texttt{SessionMiddleware} (cookie \texttt{jm\_session}, 7-day max age) and optional \texttt{ReadOnlyMiddleware} when \texttt{read\_only=true}.
Default listen address: \texttt{0.0.0.0:8001} (\texttt{config.py}).

\leadpara{Agent modules.}
Three domain agents are constructed in \texttt{bootstrap.py} and share an in-process \texttt{AgentEventBus} (\texttt{bus/event\_bus.py}):
\textbf{CandidateAgent} (\texttt{agents/candidate\_agent.py}) owns candidate profile ingestion, \texttt{JsonParser} resume parsing (\texttt{hooks/parser.py}), snapshot versioning, and vector upserts to \texttt{candidates\_collection};
\textbf{EmployerAgent} (\texttt{agents/employer\_agent.py}) mirrors this for job postings in \texttt{jobs\_collection}, including \texttt{replace\_corpus} for bulk refresh from external feeds or snapshots;
\textbf{MatchmakingAgent} (\texttt{agents/matchmaking\_agent.py}) is read-only with respect to profile stores: it loads snapshots, runs retrieval and scoring, builds \texttt{MatchResult} lists, and publishes \texttt{MATCH\_COMPLETED} events.
Each agent extends \texttt{BaseAgent} (\texttt{agents/base.py}) for status reporting exposed at \texttt{GET /agents/status}.

\leadpara{Matching core.}
Scoring and ranking live under \texttt{backend/core/}:
\texttt{scoring.py} (composite, multimodal, semantic-only, skill-only strategies; \texttt{COMPOSITE\_WEIGHTS}),
\texttt{matchmaking\_scoring.py} (pair scoring orchestration, optional constraints, calibration, feedback boost),
\texttt{similarity.py}, \texttt{skills.py}, \texttt{component\_scores.py},
\texttt{match\_explanation.py} and \texttt{explain.py} (structured and rule-based explanations),
\texttt{rrf.py} (ensemble list fusion), \texttt{fusion.py} (learned logistic combiner),
\texttt{calibration.py} (Platt scaling), \texttt{feedback\_boost.py},
\texttt{constraints.py}, \texttt{strategy\_router.py}, \texttt{cross\_encoder\_rerank.py},
\texttt{lexical.py} (BM25/TF--IDF; offline benchmarks only).
Embeddings are computed in \texttt{core/embedding.py} via Sentence-Transformers.

\leadpara{Stores.}
\textbf{Vector stores:} \texttt{stores/factory.py} selects \texttt{ChromaVectorStore} (default, \texttt{vector\_store=chroma}, persist path \texttt{backend/chroma\_db/}) or \texttt{QdrantVectorStore} (\texttt{vector\_store=qdrant}, \texttt{backend/qdrant\_db/}) behind a common upsert/query interface; cosine space is the Chroma default.
\textbf{SQLite} (\texttt{backend/app.db}, path from \texttt{Settings.sqlite\_path}): \texttt{auth/store.py} (\texttt{UserStore}, roles and sessions), \texttt{stores/feedback\_store.py} (match and user feedback rows), \texttt{stores/candidate\_activity\_store.py} (saved jobs, applications, activity log).
\textbf{Frozen JSON corpus:} \texttt{data/cvs.json}, \texttt{data/jobs.json} seed demo accounts when \texttt{seed\_demo=true}.

\leadpara{External live jobs integration.}
\texttt{core/real\_jobs\_sync.py} implements the upstream contract: paginated \texttt{GET} requests with \texttt{limit}/\texttt{skip}, field normalization (\texttt{normalize\_external\_job}), identifier deduplication, and snapshot persistence to \texttt{data/jobs\_live.json}.
\texttt{services/real\_jobs\_service.py} orchestrates sync at runtime: fetch upstream, write snapshot, call \texttt{EmployerAgent.replace\_corpus}, and optionally re-embed candidates and jobs (\texttt{reindex\_all}).
Gateway endpoints: \texttt{GET /real-jobs/status} (configuration and last sync state) and \texttt{POST /real-jobs/sync} with body \texttt{\{reindex: bool\}} (default \texttt{true}).
On startup, \texttt{bootstrap.py} loads \texttt{jobs.json}, then replaces the employer corpus from \texttt{jobs\_live.json} when that snapshot contains jobs.
Environment gates: \texttt{REAL\_JOBS\_ENABLE}, \texttt{REAL\_JOBS\_BASE\_URL}, \texttt{REAL\_JOBS\_PATH}, \texttt{REAL\_JOBS\_PAGE\_LIMIT}, \texttt{REAL\_JOBS\_TIMEOUT\_SEC}, \texttt{REAL\_JOBS\_OUTPUT\_PATH} (\texttt{backend/.env.example}).
CLI one-shot sync: \texttt{python backend/scripts/sync\_real\_jobs\_once.py}.
Daily batch requests may set \texttt{sync\_before\_run=true} (default) to pre-sync when live jobs are enabled.

\leadpara{Authentication and role separation.}
Roles are \texttt{candidate}, \texttt{employer}, and \texttt{admin} (\texttt{auth/deps.py}, \texttt{require\_role}).
Session auth endpoints: \texttt{POST /auth/register}, \texttt{POST /auth/login}, \texttt{POST /auth/logout}, \texttt{GET /auth/me}.
Role-gated routes enforce ownership at the gateway layer, e.g.\ \texttt{/candidates/me/*} and resume upload (\texttt{candidate}), \texttt{/jobs/mine/*} and description upload (\texttt{employer}), \texttt{/similar/jobs/*} (\texttt{candidate}), \texttt{/similar/candidates/*} (\texttt{employer}), \texttt{POST /system/demo/reset} (\texttt{admin}).
Matching endpoints (\texttt{/match/*}) and agent telemetry (\texttt{/agents/*}) are callable without role checks so the admin console and integration tests can invoke them directly; production portals still authenticate users before calling profile-scoped routes.

\subsection{Frontend implementation}\label{sec:4-frontend}

The UI is a single React~19 SPA (Vite build, \texttt{frontend/}) with axios session cookies and role-guarded routes in \texttt{App.jsx} (\texttt{ProtectedRoute}).

\leadpara{Candidate portal (\texttt{role=candidate}).}
Routes: \texttt{/candidate/onboarding}, \texttt{/candidate/profile}, \texttt{/candidate/matches}, \texttt{/candidate/saved}.
Pages call \texttt{frontend/src/api/client.js} with \texttt{DEFAULT\_CANDIDATE\_MATCH} (see \S\ref{sec:4-params}).
Profile save dispatches a client-side \texttt{jobmatch:profile-updated} event (\texttt{utils/profileEvents.js}); matches and saved views refetch on that signal.
Explainability UI: \texttt{MatchExplainability}, \texttt{MatchDetailsDrawer}; users can save jobs, dismiss matches, and submit applications explicitly.

\leadpara{Employer portal (\texttt{role=employer}).}
Routes: \texttt{/employer/jobs}, \texttt{/employer/matches}, \texttt{/employer/applications}.
Job editor and description upload feed \texttt{/jobs/mine/*} endpoints; reverse matching uses \texttt{DEFAULT\_EMPLOYER\_MATCH} with \texttt{mode=job\_to\_candidates}.
Applicant lists read \texttt{GET /jobs/mine/applications}.

\leadpara{Admin and evaluation view (\texttt{role=admin}).}
Route: \texttt{/admin/console} (\texttt{pages/admin/AdminConsole.jsx}).
Panels: \texttt{AgentStatusPanel}, \texttt{AgentEventStrip} (tails \texttt{GET /agents/events/recent}), \texttt{SystemConfigPanel}, \texttt{MatchControls} (manual \texttt{runMatch} / \texttt{runDailyBatch}), \texttt{ResultsPanel}, and fairness summary from \texttt{GET /system/fairness}.
Recent run metadata is cached in \texttt{localStorage} (\texttt{jm\_recent\_runs}).
Live job sync is invoked via API or CLI (\S\ref{sec:4}); a dedicated admin UI control is not yet wired.

\leadpara{Shared layout and error handling.}
All portals render inside \texttt{PortalShell} (\texttt{layouts/PortalShell.jsx}) with role-aware navigation.
Dedicated error routes (\texttt{pages/errors/ErrorPage.jsx}) present full-screen, centered recovery pages for HTTP 404/502 and unknown failures, with copy that distinguishes client-side routing errors from upstream outages.

\subsection{Data structures}\label{sec:4-data}

Contracts are Pydantic models in \texttt{backend/contracts/}; snapshots are the only objects the Matchmaking agent scores.

\leadpara{Candidate profile and \texttt{CandidateSnapshot}.}
Editable portal fields: name, skills, experience years, preferred salary, remote preference, summary, canonical resume text.
On save, \texttt{CandidateSnapshot} (\texttt{contracts/snapshots.py}) stores \texttt{id}, \texttt{name}, \texttt{skills}, \texttt{experience\_years}, \texttt{remote\_preference}, \texttt{preferred\_salary}, \texttt{summary}, monotonic \texttt{version}, \texttt{document\_text\_hash}, and fixed-length \texttt{embedding}.

\leadpara{Job profile and \texttt{JobSnapshot}.}
Posting fields: title, description, \texttt{required\_skills}, \texttt{preferred\_skills}, \texttt{required\_experience}, budget (\texttt{budget}, \texttt{budget\_min}, \texttt{budget\_max}), \texttt{remote\_policy}, optional \texttt{company}, \texttt{link}, \texttt{location}, \texttt{job\_type}, \texttt{source}, and \texttt{posted\_at} when supplied by portal or external feeds, plus the same \texttt{version}, \texttt{document\_text\_hash}, and \texttt{embedding} triple as candidates.
Vector metadata upserts store company, link, location, compensation bounds, and source for portal filters and admin inspection.

\leadpara{\texttt{MatchResult} and \texttt{MatchExplanation}.}
\texttt{MatchResult} (\texttt{contracts/matching.py}) carries \texttt{target\_id}, \texttt{target\_label}, \texttt{rank}, bi-encoder \texttt{similarity}, per-component scores (\texttt{semantic\_score}, \texttt{skills\_score}, \texttt{title\_score}, \texttt{experience\_score}, \texttt{compensation\_score}, \texttt{remote\_score}), \texttt{final\_score}, skill overlap lists, optional contact and job metadata, constraint notes, and an optional \texttt{MatchExplanation}.
\texttt{MatchExplanation} bundles \texttt{matched\_skills}, \texttt{missing\_skills}, four \texttt{FitSignal} rows (\texttt{semantic}, \texttt{experience}, \texttt{compensation}, \texttt{remote}), and \texttt{score\_breakdown} (\texttt{ScoreComponentDetail} list with weight, score, contribution).
The enclosing \texttt{MatchResponse} adds \texttt{session\_id}, \texttt{direction}, \texttt{strategy\_used}, corpus counters, agent version map, and optional rerank diagnostics.

\leadpara{Feedback and agent events.}
\textbf{Feedback:} \texttt{FeedbackStore} rows record \texttt{user\_id}, \texttt{target\_id}, \texttt{action}, optional \texttt{context\_id}, \texttt{role}, and timestamp.
Match-scoped actions: \texttt{save}, \texttt{dismiss}, \texttt{apply}; broader user actions: \texttt{contact}, \texttt{reject}, \texttt{not\_interested}.
Feedback does not rewrite embeddings; it can adjust scores only when \texttt{use\_feedback\_boost=true}.
\textbf{Agent events:} typed enums in \texttt{bus/events.py}---\texttt{CANDIDATE\_PROFILE\_UPDATED}, \texttt{JOB\_PROFILE\_UPDATED}, \texttt{CORPUS\_BOOTSTRAPPED}, \texttt{MATCH\_REQUESTED}, \texttt{MATCH\_COMPLETED}---published on the in-process bus and surfaced to the admin event strip.

\subsection{Parameter settings}\label{sec:4-params}

\leadpara{Embedding model and vector backend.}
Default embedding model: \texttt{all-MiniLM-L6-v2} (384 dimensions, \texttt{Settings.embedding\_model}).
Vector backend selector: \texttt{Settings.vector\_store} $\in \{\texttt{chroma}, \texttt{qdrant}\}$; Chroma is the default in committed settings.

\leadpara{Top-$K$ and retrieval.}
Portal defaults (\texttt{DEFAULT\_CANDIDATE\_MATCH}, \texttt{DEFAULT\_EMPLOYER\_MATCH} in \texttt{client.js}): \texttt{topK=10}, \texttt{retrieval=exhaustive} on the demo corpus (15 jobs / 30 resumes).
API contract defaults (\texttt{MatchRequest}): \texttt{top\_k=5}, \texttt{candidate\_pool=120}, \texttt{retrieval=exhaustive}; offline evaluation and regression tests use $K{=}5$ unless a driver overrides \texttt{--top-k}.
When \texttt{retrieval=ann}, shortlists come from the configured vector store before pairwise rescoring.

\leadpara{Scoring weights and modes.}
Portal requests fix \texttt{strategy=composite}, \texttt{metric=cosine}, \texttt{skillsMode=jaccard}, \texttt{semanticWeight=0.7}, \texttt{fusionMode=fixed}, with \texttt{applyConstraints=false}, \texttt{autoStrategy=false}, \texttt{useCalibration=false}, \texttt{useFeedbackBoost=false}, \texttt{explainMode=rules}.
Composite component weights in \texttt{COMPOSITE\_WEIGHTS}: semantic 28\%, skills 27\%, title 10\%, experience 15\%, compensation 10\%, remote 10\% (Eq.~\ref{eq:composite}).
RRF merge constant: \texttt{Settings.rrf\_k=60}.
Learned fusion weights load from \texttt{data/models/fusion.json}; Platt calibration from \texttt{data/models/calibration.json} ($a{\approx}2.078$, $b{\approx}2.112$).

\leadpara{Thresholds and optional boosts.}
Explainability fit labels (\texttt{match\_explanation.py}): Strong $\geq 0.85$, Good $\geq 0.65$, Moderate $\geq 0.45$, else Weak.
Rule bullets in \texttt{explain.py} use additional cutoffs (e.g.\ title $\geq 0.65$, semantic narrative bands at 0.75 and 0.55).
Hard constraint penalty default in \texttt{constraints.py}: factor $0.65$ when experience gap triggers.
Feedback boost deltas when enabled (\texttt{feedback\_boost.py}): save $+0.04$, apply $+0.06$, dismiss $-0.06$.
Cross-encoder rerank pool default: 20; disabled in production settings (\texttt{enable\_cross\_encoder\_rerank=false}).

\leadpara{External live jobs (optional).}
Gated by \texttt{REAL\_JOBS\_ENABLE=false} by default.
When enabled: \texttt{REAL\_JOBS\_BASE\_URL}, \texttt{REAL\_JOBS\_PATH} (default \texttt{/jobs}), \texttt{REAL\_JOBS\_PAGE\_LIMIT} (100), \texttt{REAL\_JOBS\_TIMEOUT\_SEC} (30), snapshot path \texttt{REAL\_JOBS\_OUTPUT\_PATH} (\texttt{data/jobs\_live.json}).
Daily batch default \texttt{sync\_before\_run=true} pre-syncs only when live jobs are enabled.

\leadpara{Vector-store update path.}
On snapshot registration the owning agent (1)~embeds canonical document text, (2)~upserts into the active vector collection, and (3)~emits a profile-updated event.
The Matchmaking agent reads snapshots, scores all or ANN-filtered pairs with the requested strategy, attaches explanations, and returns the top-$K$ list.

\subsection{Reproducibility}\label{sec:4-benchmarks}

\leadpara{Dataset files.}
Primary evaluation corpus under \texttt{data/}: \texttt{cvs.json} (30 resumes), \texttt{jobs.json} (15 jobs), \texttt{eval\_pairs.json} (47 graded query--document pairs with relevance labels).
Auxiliary assets: \texttt{fairness\_audit\_profiles.json}, frozen expected metrics \texttt{expected/paper\_progression\_summary.json}, trained auxiliary models \texttt{models/fusion.json} and \texttt{models/calibration.json}.
Research export mirror: \texttt{data/research/} (\texttt{cvs.json}, \texttt{jobs.json}, \texttt{eval\_pairs.json}, \texttt{manifest.json}).

\leadpara{Benchmark drivers.}
Python modules under \texttt{backend/benchmarks/} share \texttt{eval\_data.py} snapshot builders and \texttt{metrics.py} rank metrics.
Entry scripts include \texttt{run\_eval.py}, \texttt{run\_comparison.py}, \texttt{run\_ablation.py}, \texttt{run\_paper\_tables.py}, \texttt{run\_significance.py}, \texttt{run\_explainability\_eval.py}, \texttt{run\_fairness\_audit.py}, \texttt{run\_generate\_research\_dataset.py}, and orchestrator \texttt{research\_pipeline.py}.
One-shot wrapper: \texttt{backend/scripts/run\_research\_pipeline.py} (default \texttt{--top-k 5}).

\leadpara{Automated tests.}
Layout: \texttt{tests/unit/backend/} (Python unit tests), \texttt{tests/unit/frontend/} (Node tests for \texttt{frontend/src/utils/*}), \texttt{tests/integration/} (HTTP flows), \texttt{tests/benchmarks/} (offline eval regression).
Unified runner from repository root: \texttt{bash scripts/run\_tests.sh} (\texttt{pytest ../tests} plus Node utils).
Regression gate: \texttt{tests/benchmarks/test\_eval\_regression.py} recomputes semantic and multimodal rankings on the frozen corpus and compares nDCG@5 against \texttt{paper\_progression\_summary.json} with tolerance $\pm 0.04$ (Eq.~\ref{eq:regression}).
Live-jobs contract tests: \texttt{tests/unit/backend/test\_real\_jobs\_sync.py} (normalize, pagination mock, snapshot I/O) and \texttt{tests/integration/test\_real\_jobs\_api.py} (status endpoint; sync disabled returns HTTP~400).
Additional benchmark tests cover ablations, fusion tables, fairness audit, explainability checks, significance resampling, synthetic dataset validation, and the research export pipeline (\texttt{tests/benchmarks/*.py}).
Run backend tests from \texttt{backend/} with \texttt{pytest ../tests -q} (310 tests collected as of submission tag; declared in \texttt{requirements-min.txt}).
