# V1.1 Design · Role Portals, Auth & LLM Resume Onboarding

**Status:** Implemented (2026-05-27)  
**Supersedes (partially):** `V1-V2-SCOPE.md` auth and LLM CV parser deferrals

---

## Summary

Add **real authentication** and **three route-based portals** for a product-shaped experience:

| Portal | Role | Primary job |
|--------|------|-------------|
| Candidate | `candidate` | Upload resume → LLM extract → edit profile → find matching jobs |
| Employer | `employer` | Manage job postings → find ranked candidates |
| Admin | `admin` | Existing Match Console (agents, eval, ensemble, daily batch) |

**Naming:** UI uses **Candidate** and **Employer** (not Employee/Client). Third role is **Admin** (matchmaker/ops).

---

## Goals

1. Separate logged-in experiences for job seekers, recruiters, and admins.
2. Candidate onboarding: upload resume, AI-assisted field extraction, manual review, then job search.
3. Preserve v1 admin/eval demo without regression.
4. Implement LLM CV parsing in v1.1 (pulled forward from v2 scope).

## Non-goals (v1.1)

- OAuth / SSO / email verification / password reset
- LLM JD parser, LLM match explainer, LLM rerank (remain v2)
- Multi-tenant deployment hardening (Postgres, Redis, public deploy)
- Employer resume upload (candidate-only for v1.1)

---

## Architecture

```
/login, /register (public)
         │
         ▼
┌──────────────┬──────────────┬──────────────┐
│  /candidate  │  /employer   │   /admin     │
│   portal     │   portal     │   console    │
└──────┬───────┴──────┬───────┴──────┬───────┘
       │              │              │
       └──────────────┴──────────────┘
                      │
               FastAPI gateway
        (auth routes + existing match APIs)
                      │
         ┌────────────┴────────────┐
         │ SQLite (users, ownership) │
         │ Chroma (candidates, jobs) │
         └───────────────────────────┘
```

### Frontend stack

- React 19 + Vite 7 (existing)
- **React Router** for `/login`, `/register`, `/candidate/*`, `/employer/*`, `/admin/*`
- **`ProtectedRoute`** · session check + role guard; wrong role → redirect to role home
- **Shared components:** `ResultsPanel`, match API client, form primitives
- **Role layouts:** simplified candidate/employer shells; admin keeps full agent KPI panel

### Backend stack

- New **`backend/auth/`** module
- **Session:** HTTP-only cookie (same-origin via Vite proxy)
- **Passwords:** bcrypt via `passlib`
- **User store:** SQLite (`users` table)
- **Ownership map:** SQLite linking `user_id` ↔ candidate/job entity IDs

### LLM provider (config-driven)

| Setting | Purpose |
|---------|---------|
| `PARSER_BACKEND=llm` | Enable `LlmParser` (default for upload flow) |
| `OLLAMA_BASE_URL` | Local Ollama (recommended dev default) |
| `OLLAMA_MODEL` | e.g. `llama3.2`, `mistral` |
| `OPENAI_API_KEY` | Optional cloud provider |
| `OPENAI_BASE_URL` | Optional compatible API base |

Fallback: if LLM unavailable, return clear error and present empty manual form (no silent heuristic fill).

## Auth API

| Method | Route | Description |
|--------|-------|-------------|
| POST | `/auth/register` | `{ email, password, role }` → create user, set session |
| POST | `/auth/login` | `{ email, password }` → set session |
| POST | `/auth/logout` | Clear session |
| GET | `/auth/me` | Current user `{ id, email, role }` |

**Roles:** `candidate` | `employer` | `admin`

Registration includes role selection. Admin accounts may be seed-only in v1.1 (TBD at implementation: open admin signup vs seeded admin).

## Candidate portal

### Onboarding wizard (`/candidate/onboarding`)

1. **Upload** · PDF or DOCX, max ~5 MB, drag-and-drop
2. **Extract** · `POST /candidates/upload-resume` (multipart)
3. **Review & edit** · pre-filled form from LLM extraction
4. **Save** · `POST /candidates` with `user_id` ownership
5. **Match** · navigate to `/candidate/matches`, run candidate→jobs

### Pages

| Route | Content |
|-------|---------|
| `/candidate/onboarding` | Upload → extract → review (first-time or re-upload) |
| `/candidate/profile` | Edit saved profile |
| `/candidate/matches` | Job search results; simplified controls (no ensemble/strategy by default) |

**Hidden for candidates:** `AgentStatusPanel`, eval corpus picker, daily batch, admin ops.

### Resume extraction pipeline

```
PDF/DOCX
  → pdfplumber / pymupdf text extract
  → LlmParser.parse_candidate_from_text(text)
  → JSON validated against CandidateProfile shape
  → { extracted_fields, raw_text_preview } to frontend
  → user edits → POST /candidates → CandidateAgent.register
```

**LlmParser** (implements SDD §14 stub):

- Structured JSON output prompt
- Pydantic validation; one retry on malformed JSON
- No logging of full resume text in production mode

## New / extended API endpoints

| Method | Route | Auth | Description |
|--------|-------|------|-------------|
| POST | `/candidates/upload-resume` | candidate | multipart file → extracted fields |
| POST | `/candidates` | candidate, admin | register profile; attach `user_id` when candidate |
| GET | `/candidates/me` | candidate | owned profile |
| POST | `/jobs` | employer, admin | register job; attach `user_id` when employer |

Existing match routes unchanged; candidate/employer UIs call them with owned entity IDs.

## Data model

### SQLite: `users`

```sql
CREATE TABLE users (
  id TEXT PRIMARY KEY,
  email TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  role TEXT NOT NULL CHECK (role IN ('candidate', 'employer', 'admin')),
  created_at TEXT NOT NULL
);
```

### SQLite: ownership

```sql
CREATE TABLE candidate_ownership (
  user_id TEXT NOT NULL REFERENCES users(id),
  candidate_id TEXT NOT NULL,
  PRIMARY KEY (user_id)
);

CREATE TABLE job_ownership (
  user_id TEXT NOT NULL REFERENCES users(id),
  job_id TEXT NOT NULL,
  PRIMARY KEY (job_id)
);
```

Chroma collections unchanged (`candidates_collection`, `jobs_collection`).

## Error handling

| Scenario | Behavior |
|----------|----------|
| LLM timeout / unavailable | Toast + empty manual form; user can still save |
| Scanned PDF (no text) | Error: use text-based PDF or manual entry |
| Unauthenticated portal access | Redirect to `/login` |
| Wrong role on route | Redirect to role home |
| Duplicate email | HTTP 409 |
| Match without profile | Block: “Complete your profile first” |

## V1-V2 scope adjustments

Move from **v2 → v1.1 delivered:**

- Authentication (basic email/password + role portals)
- LLM CV parser (`LlmParser` for resume upload flow)

Remain **v2:**

- LLM JD parser, LLM explainer, LLM rerank
- OAuth, email verification, password reset
- Qdrant, Redis/NATS, public deployment hardening
